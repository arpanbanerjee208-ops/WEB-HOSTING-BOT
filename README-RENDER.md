# Deploy this project on Render

This repository is the Flask dashboard (entry point: `app.py`). Deploy it as a **Render Web Service**, not as the Telegram worker stored under `servers/FILE/extracted/`.

## Render startup command

```bash
gunicorn --workers 1 --threads 4 --timeout 120 --bind 0.0.0.0:$PORT app:app
```

The root `render.yaml` already contains this command, the build command, health check, environment settings, and a persistent disk.

## Deploy with the Blueprint

1. Extract this ZIP and push the **contents** of the extracted folder to a GitHub repository (the `app.py`, `requirements.txt`, `render.yaml`, and `templates/` folder must be at repository root).
2. In Render, choose **New + → Blueprint** and connect that GitHub repository.
3. Review the `proxy-dashboard` service and create it. Render reads `render.yaml` and installs dependencies with `pip install -r requirements.txt`.
4. In the service's Environment page, set `NORMAL_PASSWORD` to a strong password of your choice. `SECRET_KEY` is generated by the Blueprint; do not change it after users start signing in, or existing signed sessions will be invalidated. Keep `COOKIE_SECURE=true` for HTTPS.
5. Wait for the deploy to finish, then open the `onrender.com` URL. The health check is `/api/ping`.

## Manual Render setup (if not using the Blueprint)

- **Service type:** Web Service
- **Runtime:** Python 3
- **Build command:** `pip install -r requirements.txt`
- **Start command:** `gunicorn --workers 1 --threads 4 --timeout 120 --bind 0.0.0.0:$PORT app:app`
- **Health check path:** `/api/ping`
- **Environment variables:**
  - `DATA_DIR=/var/data`
  - `COOKIE_SECURE=true`
  - `SECRET_KEY=<long-random-secret>`
  - `NORMAL_PASSWORD=<your-strong-login-password>`
- **Persistent disk:** mount path `/var/data`, size 1 GB (a paid Render feature).

Generate a secret locally with:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

## Run locally

```bash
python -m pip install -r requirements.txt
python app.py
```

For a production-like local run:

```bash
gunicorn --workers 1 --threads 4 --timeout 120 --bind 0.0.0.0:5000 app:app
```

## Important hosting limitations

- The dashboard's uploaded files, JSON data, and managed server folders are stored under `DATA_DIR`. The Blueprint mounts a persistent disk there so they survive deploys and restarts. Persistent disks are not available on Render's free web-service plan; if you remove the disk or use an ephemeral filesystem, data can be lost on redeploy/restart.
- This app can launch child processes, but a Render Web Service is **not a VPS**. Render only routes public HTTP traffic to the web service's assigned port. Additional ports opened by programs launched from this dashboard will not automatically become public services, and long-running child processes may be stopped during deploys/restarts.
- Keep one Gunicorn worker. Multiple workers would each start their own background monitor threads and maintain separate in-memory process tracking.
- Do not commit `.env`, bot tokens, API keys, or other secrets to GitHub.
